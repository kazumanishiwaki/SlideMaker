# SlideHarness Next v0.11 — ゼロベース製品仕様

## 0. 文書情報

- 状態: Draft
- 目的: 次期版の製品要件と品質基準を定義する
- 位置づけ: 現行v0.10の追補ではなく、ゼロベースで再設計する次期仕様
- 製品定義: 任意テンプレート対応の提案資料生成 + 画像生成
- 実装方針: n2p-pptx／現行SlideHarnessのコード流用を前提にしない

現行v0.10のコード、仕様、Golden Sampleは比較資料として保存する。
本仕様の承認前に、現行実装をこの仕様へ合わせて変更しない。

## 1. 製品ビジョン

原稿と任意のPowerPointテンプレートから、営業提案書・企画書として情報が過不足なく整理され、テンプレートのデザイン文法を反映し、必要な画像・グラフ・表・フロー図を備えた編集可能なPPTXを生成する。

品質の中心は「一枚のスライドとしてまとまっていること」とする。

- 情報を削りすぎない
- 無意味な空白を残さない
- 要素を詰め込むだけにしない
- テンプレートを単なる配色サンプルにしない
- 画像を空白埋めにしない
- 図表を画像へ焼き込まない
- PowerPoint上で実務的に編集できる

## 5. 最上位品質原則

### 5.1 1ページ1主張、複数の根拠

1ページには原則として1つのPrimary Messageを置く。
ただし、1ページを1つのテキスト要素だけにしてはならない。

通常ページは次の構成を基本とする。

- Primary Message: 1件
- Supporting Unit: 2〜5件
- Evidence / Visual: 0〜2件
- Takeaway / Note: 必要な場合のみ1件

Supporting Unitには、根拠、比較項目、機能、工程、条件、数値、具体例を含める。

### 5.2 情報網羅性

スライド構成を作る前に、原稿の情報単位を分類し、採用、統合、分割、Appendix、除外のいずれかを明示する。

理由なく情報を削除しない。
特に次はContent Blockingとする。

- 金額
- 日付・期間
- 数値
- 適用条件
- 対象範囲
- 例外
- 注意事項
- 法務・セキュリティ条件

### 5.3 版面密度

表紙、中表紙、単独メッセージ、クロージングを除き、通常ページではコンテンツ領域を有効に使う。

- 標準ページの意味ある占有率: 55〜85%
- 表・比較・工程ページの意味ある占有率: 65〜90%
- 画像中心ページの意味ある占有率: 60〜95%
- 単独メッセージページの意味ある占有率: 30〜70%

背景色、全面背景画像、テンプレート固定装飾は占有率へ加算しない。

次はDesign Blockingとする。

- 通常ページで、説明できない連続空白がコンテンツ領域の35%を超える
- 内容量に対してカードやテキスト枠が過大である
- 要素が上部または下部だけに偏り、反対側が空いている
- 2件しかない内容を3〜4件用グリッドへ配置する
- 短い文章を巨大な文字へ拡大するだけでページを成立させる

### 5.4 可読性

標準16:9資料の初期値は次とする。テンプレートの階層比を優先しつつ、安全範囲内で調整する。

| 役割 | 標準 | 下限 |
|---|---:|---:|
| 表紙タイトル | 24〜34pt | 22pt |
| 本文ページタイトル | 16〜24pt | 15pt |
| カード・中見出し | 11〜15pt | 10pt |
| 本文 | 10.5〜13pt | 9.5pt |
| 表・図内文字 | 9〜11pt | 8.5pt |
| 注釈 | 8.5〜10pt | 8pt |

下限未満へ縮小する前に、文章圧縮、再構成、領域変更、別レシピ、ページ分割を試す。

## 6. テンプレート適応

### 6.1 基本方針

テンプレートは、生成する内容構成を固定するものではない。
テンプレートからデザインシステムを抽出し、内容に適した版面へ適用する。

### 6.2 抽出対象

- スライドサイズと比率
- 背景
- カラーパレット
- フォントと文字階層
- タイトル軸・本文軸
- 標準マージン
- グリッド
- ロゴと隔離領域
- ヘッダー・フッター
- 罫線・角丸・影・透明度
- 写真枠・マスク・クロップ傾向
- アイコン・反復装飾
- 表・グラフ・図形のスタイル
- 表紙・中表紙・本文・クロージングの代表構成

### 6.3 Template Design System

解析結果を次の4層へ正規化する。

1. Tokens
   - color
   - typography
   - spacing
   - stroke
   - radius
   - effect
2. Chrome
   - logo
   - header
   - footer
   - page number
   - fixed ornament
3. Components
   - title
   - card
   - callout
   - table
   - chart
   - image frame
4. Pattern Evidence
   - cover
   - section
   - content
   - data
   - visual
   - closing

### 6.4 テンプレート忠実度

次の順で評価する。

1. ブランド識別要素が保持されている
2. 文字階層と整列軸が一致している
3. 色・罫線・角丸・余白のリズムが一致している
4. 写真や図表の扱いが一致している
5. ページ間で一貫している

元PPTの完成スライドをそのまま複製することは必須ではない。
ただし、マスターに存在しない重要装飾もPattern Evidenceとして解析対象に含める。

### 6.5 フォールバック

テンプレートから十分な規則を抽出できない場合は、以下をユーザーへ明示する。

- 抽出できた要素
- 推定した要素
- 標準規則へフォールバックする要素
- 忠実度が下がるページ種別

無根拠にテンプレート準拠を主張しない。

## 7. スライドレシピ

### 7.1 レシピの役割

Layout Familyだけでなく、内容量と視覚構造を含む具体的なSlide Recipeを使用する。

各レシピは次を持つ。

- 対応する意味構造
- 必須スロット
- 任意スロット
- Supporting Unitの最小・最大数
- 推奨文字量
- 比率と整列規則
- 画像スロット
- 図表スロット
- 密度範囲
- 空白許容範囲
- オーバーフロー時の代替レシピ

### 7.2 初期レシピ一覧

- cover
- agenda
- section
- statement
- title_body
- title_body_callout
- two_column_equal
- two_column_asymmetric
- three_column
- card_grid_2x2
- card_grid_3x2
- comparison
- comparison_matrix
- feature_list
- case_study
- screenshot_annotation
- image_text
- full_visual
- kpi
- bar_chart
- line_chart
- donut_chart
- table
- process
- timeline
- cause_effect
- relationship
- containment
- pricing
- schedule
- organization
- closing_cta

### 7.3 レシピ選択

意味構造、情報量、視覚素材、テンプレート適合度から候補を評価する。

候補選択時に以下を記録する。

- 選択理由
- 不採用候補
- 内容適合度
- テンプレート適合度
- 予測占有率
- 文字サイズ予測
- 代替レシピ

モデルは自由な絶対座標を直接生成しない。
モデルはレシピ、領域比率、スロット優先度を決め、座標は決定論的レイアウトエンジンが解決する。

## 8. 画像生成

### 8.1 画像の役割

画像生成は次の用途を持つ。

- 表紙・キービジュアル
- 説明イラスト
- コンセプトビジュアル
- 製品・利用シーンの補助
- テンプレートに合う背景装飾
- セクション装飾
- 図表を補助する視覚要素

装飾目的の画像生成を許可する。
ただし、テンプレートのリズムを補強し、テキストの可読性と情報構造を損なわないことを条件とする。

### 8.2 優先順位

1. ユーザー指定画像
2. 原稿・参考資料に含まれる画像
3. テンプレート内の再利用可能な画像・装飾
4. 生成画像

### 8.3 生成順序

1. Slide Recipeを選ぶ
2. 画像スロットの位置・比率・役割を決める
3. Template Design Systemからアートディレクションを作る
4. プロンプトを生成する
5. 画像を生成する
6. クロップ・色調・コントラストを調整する
7. 実レンダーで文字との共存を確認する

先に画像を作り、空いた場所へ後から押し込まない。

### 8.4 画像QA

- スロット比率との一致
- 主題の欠損がない
- 文字領域が確保されている
- テンプレートの色・質感と調和する
- 不自然な文字・ロゴが画像内にない
- 不要なウォーターマークがない
- ページ間で画風が破綻していない
- 過剰な装飾になっていない

---

## 9. グラフ・表・フロー図

### 9.1 共通原則

- 画像として生成しない
- 元データを保持する
- ラベル、凡例、軸、数値を編集可能にする
- テンプレートの色・線・文字階層を適用する
- 意味構造に合う図を選ぶ

### 9.2 グラフ

- 棒: 項目比較
- 折れ線: 時系列変化
- 円・ドーナツ: 限られたカテゴリの構成比
- 散布: 2変数の関係
- ウォーターフォール: 増減要因

3Dグラフは標準で使用しない。
円・ドーナツは5カテゴリ以下を推奨する。

### 9.3 フロー図

- sequence
- cause_effect
- decision
- relationship
- containment
- timeline

ノードとコネクターをネイティブ図形として生成する。
意味のない等分カードへ変換しない。

### 9.4 表

- ヘッダーと本文の階層を明確にする
- 行・列の多い表は分割またはAppendix化を検討する
- 強調セルは意味のある箇所だけに限定する
- テキスト縮小だけで収めない

## 10. 生成フロー

```text
1. Input Ingest
2. Content Modeling
3. Template Compilation
4. Deck Outline / Coverage Review
5. Slide Recipe Planning
6. Representative 3-page Render
7. Human Review Gate
8. Image Generation / Asset Resolution
9. Full Composition
10. Actual-render QA
11. Final Review / Export
```

### 10.1 代表3ページ

全ページ生成前に、性質の異なる3ページを必ず作る。

- 標準本文ページ
- 図表または複雑な構造のページ
- 画像を使うページ

3ページの確認項目:

- テンプレートらしさ
- 情報密度
- 文字サイズ
- 余白
- 画像トーン
- 図表の編集可能性

ユーザーまたは人間レビューで承認されるまで、全ページへ展開しない。

## 11. QA

### 11.1 Technical Blocking

- PPTX破損
- スライド外配置
- 意図しないオブジェクト重複
- テキストはみ出し
- 画像アスペクト比破壊
- 未解決アセット
- 編集不能な必須図表
- テンプレート固定要素の欠損

### 11.2 Content Blocking

- 原稿の重要情報欠損
- 数字・条件・日付の変化
- 原稿にない事実の追加
- 制作メモやプロンプトの混入
- Primary Messageと本文の不一致
- 図表データと表示値の不一致

### 11.3 Design Blocking

- 不要な大空白
- 内容量に合わないレシピ
- 過小文字
- 不自然な改行
- 整列軸の不一致
- テンプレートとの重大な不整合
- 画像と文字の競合
- ページ間の密度・装飾リズムの破綻
- 空カード・空図形
- 同じ構成の過剰反復

Technical、Content、DesignのBlockingが0になるまでFinal Exportしない。

### 11.4 修正上限

同じ原因で無制限に再生成しない。

1. 決定論的修正
2. 代替レシピを1回試す
3. 文章構造またはページ分割を1回見直す
4. 解消しない場合はREVIEW_REQUIRED

## 12. 部分再生成

変更範囲は最小にする。

| 変更 | 再生成範囲 |
|---|---|
| 画像差し替え | 対象画像、対象ページ、ページQA、全体調和QA |
| 文言修正 | 対象テキスト、対象ページ、Content QA |
| レイアウト修正 | 対象Slide Spec、Compose、対象ページQA |
| テンプレート変更 | Template Design System、全ページCompose、全体QA |
| 構成変更 | Deck Outlineと影響するSlide Spec |

LOCKEDページは、テンプレート全体変更など明示的に必要な場合を除き変更しない。

---

## 13. 非目的

- 任意テンプレートの全オブジェクトを完全複製すること
- すべてのページへ画像を追加すること
- 空白を埋めるためだけの文章生成
- すべての資料を投影用の大文字・低密度へ統一すること
- 原稿の条件を短いマーケティングコピーへ置き換えること
- PowerPoint外でしか編集できない図表を標準出力にすること
- 自動修復を無制限に実行すること

## 14. 受け入れ基準

### 14.1 同一原稿・異なるテンプレート

同じ原稿を3種類以上のテンプレートで生成し、次を満たす。

- 必須情報の保持率100%
- ページ構成の主要意図が維持される
- 各テンプレートの識別要素が反映される
- 通常ページの不要空白Blockingが0
- Technical / Content / Design Blockingが0

### 14.2 編集可能性

- グラフの数値をPowerPoint上で変更できる
- 表のセルを編集できる
- フロー図のノード・線・ラベルを編集できる
- 画像をPowerPoint上で差し替えられる

### 14.3 画像生成

- 指定スロットに合う比率で生成される
- テンプレートに合う画風である
- 文字領域を侵食しない
- 生成待ち・未解決画像がある状態で完成扱いにしない

### 14.4 人間評価

各Golden Sampleは、次の5項目を人間が5段階評価する。

- 情報のまとまり
- テンプレートらしさ
- 読みやすさ
- 画像・図表の有用性
- 提案資料としての完成度

全項目4以上、かつ「そのまま社外提示できる」が承認条件である。

## 15. Golden Sample計画

最低3系統を用意する。

1. ミニマル企業テンプレート
2. 装飾の多いブランドテンプレート
3. 写真中心のビジュアルテンプレート

同一原稿を使い、テンプレート変更によって内容網羅性と版面品質が崩れないことを検証する。

各系統で次のページを含める。

- 表紙
- 2×2または3カラム
- 比較表
- グラフ
- フロー図
- 画像＋説明
- 料金またはスケジュール
- クロージング

## 16. ゼロベース実装原則

- n2p-pptxと現行SlideHarnessのコードコピーを前提にしない
- 既存関数名、ファイル構成、データモデルへ合わせない
- 要求と受け入れ基準から必要な構造を設計する
- 再利用する場合は、再利用のほうが新規実装より明確に優れることを個別に確認する
- 参考にした概念と、実際に採用した設計を分離して記録する
- 外部ライブラリは編集可能性、描画忠実度、保守性の比較検証後に選定する
- 実装言語は現行コードの都合だけで決めない

本仕様では、既存コードとの互換性より生成品質を優先する。
